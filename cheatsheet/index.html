Vim: moving and editing

All of these keys work in Normal mode (green).

Moving through a file blue dashes: the part on screen

Verb + where delete d · change c · copy y, then a motion. The same key twice means the whole line.

dw
delete to the next word
proxy_pass backend_server timeout;→proxy_pass timeout;
d$
delete to the end of the line
proxy_pass backend_server timeout;→proxy_pass
dd
delete the whole line
proxy_pass backend_server timeout;→(line removed; p puts it back)
cwapiEsc
change to the end of the word
proxy_pass backend_server timeout;→proxy_pass api timeout;
ci"/srvEscvim
change inside the quotes
root "/var/www";→root "/srv";
yyp

allow 10.0.0.1;→allow 10.0.0.1;
allow 10.0.0.1;

p pastes what was deleted or copied · x deletes one character · . repeats the last change · u undoes it

Colour shows the level: session ⊃ window ⊃ pane.

When you are stuck after C-b

?every key (q closes)
/what the next key does (3.1+)
:type a tmux command

Nothing responds? You are in copy mode or a menu: press q or Esc. To reach a tmux opened inside this one, press C-b twice.

Vim recipes

Real tasks, key by key. Each key is coloured by the mode it leaves you in; grey means type it as shown. Start in Normal mode.

Change a value

vi redis.conf→/maxclientsEnter→wcw20000Esc→:wq
port 6379 maxclients 10000 save 900 1
/maxclients
→
port 6379 maxclients 20000 save 900 1
"redis.conf" written

w steps from the name onto the value; cw replaces just that word.

Comment out a line

/listen 80Enter→I#Esc→:wq
server { listen 80; }
/listen 80
→
server { # listen 80; }
"site.conf" written

I types at the start of the line, wherever the cursor is.

Comment out several linesvim

Ctrl-vjj→I#Esc
listen 80; listen 443; server_name a;
-- VISUAL BLOCK --
→
#listen 80; #listen 443; #server_name a;
 

Ctrl-v selects a column; text typed after I lands on every line when you press Esc.

Copy a line, then edit the copy

yyp→wC10.0.0.2;Esc
allow 10.0.0.1; deny all;
 
→
allow 10.0.0.1; allow 10.0.0.2; deny all;
 

p pastes below (P above). C replaces to the end of the line.

Delete lines

3dd3 lines from the cursoror:2,4d
a = 1 b = 2 c = 3 d = 4 e = 5
 
→
a = 1 e = 5

Vim reports how many lines went. p puts them back below.

Replace everywhere, one at a time

:%s/old/new/gcEnter→each match:yorn
host = old.lan backup = old.lan
replace with new (y/n)?
→
host = new.lan backup = new.lan
2 substitutions

% every line, g every match on a line, c asks each time.

Read a log from the end

view app.log→G?ERROREnter→nolder
12:01 ERROR disk full 12:05 ok 12:09 ERROR timeout 12:10 ok
?ERROR
→
12:01 ERROR disk full 12:05 ok 12:09 ERROR timeout 12:10 ok
?ERROR

view is read-only. ? searches upwards, so n goes further back. :q leaves.

Saved, but no permissionvim

:w !sudo tee % >/dev/nullEnter→L
127.0.0.1 localhost 10.0.0.5 db
E212: Can't open file
→
127.0.0.1 localhost 10.0.0.5 db
W12: changed (L)oad

For a root file opened without sudo. L loads the version you just saved.

Throw your changes away

:qrefused?→:e!or:q!
port = 9999 mode = prod
E37: No write since…
→
port = 8080 mode = prod
:e! reloaded "app.ini"

:e! goes back to the saved file; :q! leaves without saving. The disk is untouched.

tmux recipes

Real tasks, key by key. C-b … means press C-b, let go, then the key.

A job that survives logout

tmux new -s deploy→start the job→C-b d→latertmux a -t deploy
$ ./deploy.sh uploading… 42%
[deploy] 0:bash*
→
$ tmux a -t deploy uploading… 87%
[deploy] 0:bash*

In between, the shell said [detached (from session deploy)] and the job kept running.
